# 동백 ONE — 지역상생 데이터 분석 작업 지시서 (Claude Code용)

> 사용법: Claude Code에 "brief.md를 읽고 STEP 0만 수행해. 끝나면 결과를 요약하고 멈춰." 처럼 **단계별로** 지시한다.
> 이 문서의 모든 경로는 담당 폴더 `data-analysis/` 기준이다. 담당 폴더 밖에는 아무것도 만들거나 고치지 않는다.

---

## 0. 역할과 원칙

- 이 작업은 프로젝트의 **데이터 분석 파트**만 다룬다. 결제 엔진·DB 스키마·원장·Streamlit 앱 본체는 다른 팀원 담당이므로 수정하지 않는다.
- **결과는 실제 효과가 아니라 공공데이터 기반 추정·시뮬레이션으로만 표현한다.**
- **보안**
  - 공공데이터와 합성 데이터만 사용한다. 실제 개인정보는 사용하지 않는다.
  - API 키는 `.env`의 `DATA_GO_KR_KEY`에만 둔다. 코드·노트북·커밋·출력물에 키를 넣지 않는다. `.env`는 git 추적에서 제외한다.
  - 가맹점 데이터의 사업자번호·대표전화는 저장하지 않는다. 성명이 들어간 상호(개인택시 등)는 가명화한다.
- **기준 시점: 2026-06-30.** 이후 자료는 쓰지 않는다(2026-09 캐시백 15% 한시 상향 제외). 원본은 한 날짜에 내려받아 `data/raw/`에 고정하고 다시 받지 않는다. 내려받은 날짜를 `docs/data_inventory.md`에 기록한다.
- 모든 숫자에 **출처 또는 "가정"**을 표시한다.
- 각 STEP이 끝나면 결과를 요약 보고하고 멈춘다. 사람의 판단이 필요한 곳(업종 매핑, 가정값)은 초안을 만든 뒤 질문한다.

## 1. 프로젝트 맥락

- **동백 ONE:** 통합카드 한 장으로 결제하면
  - 캐시백 대상 동백전 가맹점 → 동백전 우선 결제
  - 연매출 30억 원 초과 가맹점·동백전 불가 매장 → 연결 카드로 결제하고, **그 결제의 카드 혜택을 동백전으로 적립**
- **분석 목적:** 동백전을 쓸 수 없는 곳에서의 소비로 생기는 카드 혜택이 동백전으로 적립되어 가맹점에서 쓰일 수 있는 구조의 근거를, 공공데이터 기반 추정(동백전 적립 추정액)으로 만든다.

| 질문 | 내용 |
|---|---|
| ① 전제 | 캐시백이 커졌을 때 동백전 사용 가능 업종의 소비 비중이 늘었나 |
| ② 규모 | 부산 소비 중 동백전을 쓸 수 없는 업종의 소비는 얼마인가 → 동백전 적립 추정액 |
| ③ 도착지 | 행정동별 소비와 가맹점 분포를 비교하면 동백전 적립 추정액이 어디에서 쓰일 수 있는가, 사각지대는 어디인가 |
| ④ 지속성 | 은행 손익분기 계산에 넘길 입력값 표 |

## 4. 작업 단계

### STEP 0 — 데이터 점검 (가장 먼저)

- 각 원본별: 행 수, 컬럼명, dtype, 기간(기준년월 min/max), 결측률, 주요 컬럼 고유값 수
- **D1 핵심 판정:** `업종대분류명` 고유값 전체 목록을 출력한다.
  - 대형마트, 주유소, 온라인, 직영 편의점처럼 동백전을 쓸 수 없는 업종을 **구분할 수 있는지** 판정한다.
  - 판정 결과: `가능 / 부분 가능 / 불가` + 근거 3줄
- D1 금액 단위(원/천원)와 "월별 일평균"의 의미를 확인한다. 월 합계 = 일평균 × 해당 월 일수.
- D4: 부산은행 제공분(`I0000014`) 필터 후 건수, 표준산업분류코드 분포, 사업자 상태 분포
- D1(행정동)과 D4·D6(법정동/주소)을 연결할 수 있는지 확인
- **산출:** `docs/data_inventory.md` (데이터별 표 + 판정 결과)
- **멈추고 보고**

### STEP 1 — 정제·매핑

- `ref/industry_map.csv` 초안: D1 업종 ↔ 동백전 사용 여부
  - 값: `가능 / 결제만(캐시백 0) / 불가 / 불명`
  - 근거 열 포함. **초안 작성 후 멈추고 사람 검토 요청**
- 행정동 코드 통일 (`ref/dong_code_map.csv`)
- 가명화: 성명 상호 처리, 사업자번호·전화번호 컬럼 제거
- 기준 시점 필터: 2026-06 이후 행 제거
- 산출: `data/processed/*.parquet` 또는 CSV

### STEP 2 — 분석 ① 정책 전후 비교

- 질문: 캐시백 상향 후, 동백전 사용 가능 업종의 소비 비중이 불가 업종 대비 늘었나?
- 방법
  1. 월별 `가능 업종 소비 / 불가 업종 소비` 비율 시계열
  2. 정책 시점 전후 3·6개월 평균 비교
  3. 계절성 통제: 전년 동월 대비
  4. (가능하면) 이중차분 회귀: 가능 업종 = 처리군, 불가 업종 = 비교군, 월·행정동 고정효과 (statsmodels)
- **결과 문장에 인과 단정 금지.** "같은 시기 다른 정책·계절 요인이 섞일 수 있음"을 한계로 명시
- 산출: `outputs/charts/01_ratio_timeseries.png`, `outputs/tables/01_before_after.csv`, `outputs/for_streamlit/policy_ratio_monthly.csv`

### STEP 3 — 분석 ② 규모

- 최근 12개월(2025-07 ~ 2026-06) 부산 전체 소비 중 동백전 불가 업종 비중과 연간 금액
- 동백전 적립 추정액 = 불가 업종 연간 소비 × 카드 혜택률(0.5/1.0/1.5%) × 이용자 비중(0/5/10%) → 3×3 표
- 비교 기준: 동백전 연간 발행액 대비 비율
- 산출: `outputs/tables/02_out_spend.csv`, `outputs/for_streamlit/region_return_scenarios.csv`

### STEP 4 — 분석 ③ 도착지

- 행정동별 동백전 가맹점 수(영업 중) / 전체 상가 수 → 가맹 비율
- 행정동별 소비 규모 vs 가맹 비율 → 사분면 분류
  - 소비 많고 가맹 적음 = **적립 사용 사각지대**
- 지도: folium 또는 plotly. 행정동 경계 GeoJSON이 필요하면 멈추고 질문
- 산출: `outputs/charts/03_quadrant.png`, `outputs/charts/03_map.html`, `outputs/for_streamlit/dong_merchant_gap.csv`

### STEP 5 — 은행 손익 입력값

- 은행 사업성 담당의 엑셀 모델에 넘길 입력값 표만 만든다. 손익 계산 자체는 하지 않는다.
- 산출: `docs/assumptions.csv` (항목, 값, 단위, 출처/가정, 비고)

### STEP 6 — PRD 초안

- `docs/prd_6_3_6_4_draft.md`
  - 6.3 핵심 컬럼·파생변수 5~10개 정의 (예: 월 합계 소비액, 불가 업종 비중, 가맹 비율, 동백전 적립 추정액)
  - 6.4 품질 점검(결측·중복·기간·단위)과 한계
